# 即时保存与退出实施计划

目标：拍摄即保存，编辑即更新，预览随时退出，后台继续处理。以本次用户提供的九节方案为实施约束，继续 feat/issue-2-history-rescan，更新 PR #4，不合并。

方案：保留 DocumentStore / HistoryRepository，使用每文档原子 JSON 清单作为可靠提交点，历史索引可恢复重建。原图为不可变文件，页面缓存可重建；应用级 DocumentSaveCoordinator 按 ID 隔离任务与状态，缓存提交核对页面内容版本。旧 schemaVersion=1 清单继续可读，不主动改写未编辑的历史记录。普通导航不做磁盘保存或 PDF 生成。

## 实施顺序

- [x] 先写设备端到端复现：相机确认后未进入预览即有可靠记录、五页即时返回、新旧会话隔离、编辑恢复、无主动 PDF。
- [x] DocumentStore：扩展既有 schemaVersion=2 原子清单、独立原图与缓存、兼容旧格式、删除标记、恢复索引；失败不覆盖有效清单。
- [x] DocumentSaveCoordinator：应用级协程，合并索引请求，单页处理队列，版本核对，失败状态与重试。
- [x] ScanFlow / ScanViewModel：CameraX 文件输出、稳定 ID、按操作提交、移除预览 snapshotFlow 保存与导航等待；历史返回入口、三个按钮文案不变。
- [x] 构建、真实设备回归、独立审查与修复；按用户要求缩减末轮验证，结果及范围见 issue-2-immediate-save.md。

## 必须覆盖的失败模式

1. 原图写入或清单提交失败不能报拍摄成功；进程终止后可恢复已确认拍摄和编辑。
2. 旧文档缓存晚到不能覆盖最新裁剪、旋转、排序，也不能写入新文档；删除后不能复活。
3. 索引提交失败保留有效清单，首页显示失败并可重试；重启能从清单恢复。
4. 仅更新必要文件；原图不随预览、重排、返回重写；缓存缺失能按高清原图重建。
5. 五页返回弹窗和切页无保存遮罩，分享/打印才生成 PDF；历史续扫返回原入口。

验证：沿用 tools/run-history-rescan-e2e.ps1 的 JDK/SDK 与设备入口，新增固定 output/immediate-save-e2e 工件目录，包含日志、截图、耗时与跨进程阶段结果。不清空用户数据。记录实际执行范围及未验证项。
