# Issue #2 实施与验收记录

> 本文保留初期实现及验收记录。当前增量资产结构和按需 PDF 见[性能与架构优化](issue-2-performance-optimization.md)；最新拍摄、编辑提交及退出恢复机制见[拍摄即时保存与预览即时返回](issue-2-immediate-save.md)。

## 目标与设计

依据 Issue #2：历史列表 → 现有多页预览 → 添加 → 现有扫描/相册 → 原预览 → 自动更新同一记录。仅改造文件扫描，OCR、证件和其他工具保持既有行为。不开发 Issue #3 的风格界面。

采用 JSON + 文件系统，不增加数据库依赖。每次保存先生成独立版本目录，包含逐页原图、处理图、预览图、编辑参数和 PDF；全部成功后用 AtomicFile 更新历史索引指针。失败不覆盖前次版本。成功后清理未引用版本，删除记录后清理其资产。页面 ID 与文档 ID 稳定。

历史页面仅常驻缩小预览图，编辑当前页、导出当前页时按需读取高清图。页面状态签名包括顺序、ID、内容版本、裁剪、矫正、旋转、风格；单个保存消费者在页面处理完成后保存，成功后记录签名，无修改不写盘。

## 实施前失败模式

1. 恢复缺页、页序错乱或编辑参数丢失；替换导致原页 ID 改变。
2. 只观察页 ID 导致旋转、排序、编辑、删除漏存。
3. 尚未处理完成就保存，或多个保存任务乱序覆盖。
4. 无修改打开/退出仍重建 PDF；保存失败后反复自动重试。
5. 图片/PDF/索引任一步失败破坏前次版本；索引提交前清理有效数据。
6. 几十页原图常驻导致内存耗尽；高清导出误用缩略图。
7. 返回退出丢失入口；系统返回绕过保存遮罩；删除最后一页留下旧记录。
8. 分享、打印、相册追加和既有智能手拍/自动拍发生回归。

## 文件结构与提交点

```text
files/history/
  records.json                         # AtomicFile 原子索引
  documents/<document-id>/<version>/
    document.json                      # schemaVersion=1，pages 数组即页序
    document.pdf                       # 可再生成的输出
    thumbnail.jpg                      # 随首个页面及其旋转更新
    <page-id>/
      source.png                       # 现有扫描流程得到的原始输入，无损保存
      processed.png                    # 未叠加页面旋转的处理图
      preview.jpg                      # 长边不超过 640 像素
```

索引记录文档 ID、类型、标题、创建时间、最后修改时间、页数、PDF/缩略图/清单路径及状态指纹。每页记录 ID、内容版本、归一化四角坐标 `quad`、`correctionMode`、旋转角度 `rotationDegrees` 和预留 `imageStyle="default"`。四角与矫正模式决定透视变换，数组位置决定顺序。替换保留页 ID、更新内容版本，编辑保留页 ID，旋转与重排不改 ID。

保存先在独立目录写入并同步全部图片、清单和 PDF，最后原子替换索引。索引操作使用进程内共享锁；文件同步/提交失败会抛出并删除本次未提交目录，前次索引与资产未被覆盖。保存成功后才清理无引用的旧版本和中断产生的孤立目录；清理失败仅记录日志，不把已提交结果误报为失败。删除先提交索引，再清理文档目录。实现核对了 Android 官方 [AtomicFile 文档](https://developer.android.com/reference/androidx/core/util/AtomicFile)，使用项目已有 AndroidX Core 1.18.0 的实现，在所有支持系统上统一采用 `.new` 暂存和原子替换，显式提供线程互斥并检查暂存文件是否完成提交。独立审查发现平台实现因 Android 版本而异后，已通过检查本机依赖的实际类确认该行为，未新增依赖。

## 恢复、修改检测与交互

- Document 点击读取清单，直接进入现有 `PreviewResultScreen`；OCR/证件仍调用原打开流程。
- 历史恢复只加载小预览图，原图与处理图保留文件路径。编辑当前页面时按需读取；PDF、图片分享与打印逐页读取高清处理图并回收临时图片，保留原有输出接口。
- 状态指纹覆盖页序、页 ID、内容版本、裁剪、矫正、旋转及预留风格；忽略文件路径和 Bitmap 实例，避免恢复或保存后重绑定路径引发重复保存。
- 单个 `snapshotFlow` 消费者仅在预览、所有页面处理完成且状态不同于最后保存时写盘。保存期间使用原处理遮罩阻止冲突操作并消费系统返回。相机拍摄阶段不进行 PDF 保存。
- 保存成功后保持记录 ID，更新已保存指纹，释放页面原始/处理 Bitmap 的常驻引用；失败显示重试或放弃本次修改。提交成功的 ID 在后续界面处理前记录，防止重复建档。
- 保存完成的历史预览返回原首页或全部文档入口；添加相机中关闭回到原预览。取消边缘编辑不会修改已保存页。最后一页被删除（含排序页删除全部页）时删除原记录。
- 历史索引在 IO 线程读取，避免系统重建 Activity 时等待后台保存而阻塞主线程。

## 画质与排序优化

- 文件扫描拍摄目标从 2048×1536 提高至 4000×3000，输入和透视校正上限为长边 4096。相册单页编辑保留高分辨率源图，检测/边缘调整仍用 2200 工作图；OCR、证件和表格保留原有尺寸及行为。
- 历史及排序常驻 640 缩图；现有预览界面仅为当前页异步读取最长边 2048 的详细图，离开当前页后释放状态引用，避免每页长期持有高清 Bitmap。异步处理完成的 Bitmap 与路径都会触发详细图刷新。
- 多页处理完成的高清图逐页写入 `cache/document-page-processing/`，不在页面列表中累积处理图和复核图；临时校正 Bitmap 在增强后释放。成功提交永久文档后清理对应临时文件，放弃文档也清理；清理失败只记日志。处理失败保留已完成页的路径，重试复用。
- 排序拖动以稳定页面 ID 为手势键和拖动标识，换位后不重启监听；使用最新列表计算位置，松手恢复格位。拖动卡片置于上层，删除也按 ID 定位，避免换位后删除旧索引对应页。

## 范围与限制

不实现旧 PDF 兼容/迁移，不实施 Issue #3 滤镜。新格式依赖清单及页面文件，PDF 不是编辑恢复来源。每次有效保存重新生成 PDF 并暂存一份完整新版本，保存期间需要足够可用空间；未确认保存的相机/编辑内容在进程被系统直接终止后不会恢复。几十页高分辨率下的峰值内存及相册路径尚待真机验证。
