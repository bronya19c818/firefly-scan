# 拍摄即时保存与预览即时返回

本轮以已验收提交 `14378cb` 为基线，在 `feat/issue-2-history-rescan` 上改造保存与导航机制。保留现有扫描界面、退出弹窗三个动作、增量资产、`PageProcessingQueue`、高清处理算法及按需 PDF，不涉及 Issue #3。

## 保存时机

| 环节 | 调整前（14378cb） | 调整后 |
| --- | --- | --- |
| 首次拍摄 | 页面在内存和界面处理队列中，预览阶段才触发清单保存 | CameraX 输出 JPEG 文件，原图同步落盘并原子提交清单后，才增加页数和提示拍摄成功 |
| 文档身份 | 首次保存时获得记录 ID | 进入新扫描即确定稳定 ID；历史追加复用原 ID |
| 旋转、排序、裁剪、删除 | 预览中的状态指纹变化触发保存 | 操作提交小型原子清单，原图不因参数变化重新编码 |
| 返回 | 保存中或指纹未追上时，普通返回被忽略 | 普通返回不检查保存、增强或 PDF 状态；新扫描的三个退出动作立即响应，历史文档返回原入口 |
| 后台任务 | 回调读取当前界面的页面与文档 ID，退出会 reset 队列 | 应用级协调器持有独立页面快照，任务固定归属文档；离开界面只解除引用 |
| PDF | 已按需生成 | 继续只在分享、导出、打印或明确打开 PDF 时生成 |

## 可靠数据与可重建缓存

- 原图保持不可变资产；CameraX JPEG 从 `history/captures/<document-id>/` 进入现有 `pages/<page-id>/<revision>.jpg`，不经 Bitmap 转 PNG。既有 PNG 原图继续可读。
- 现有 schema 2 清单补充可选的文档 ID、名称、创建/修改时间、指纹和递增版本。清单使用现有 AndroidX `AtomicFile`，显式同步和检查；旧 schema 1/2 清单保持兼容。
- 清单是已确认操作的恢复依据，历史索引在后台合并。索引写入失败或进程在合并前结束，重新加载仍可从清单恢复页面及最新参数。
- 常规编辑只同步写入当前文档的小型清单，不编码图片、生成 PDF、更新封面或清理目录。文件编码及相册提交在 IO 阶段完成。
- 协调器按文档隔离提交和失败重试，合并索引请求，复用现有按页队列；所有文档合计最多两个页面处理任务。新旧会话不会共用文档身份。
- 新拍摄与相册追加按稳定页面 ID 合并到最新文档，编辑提交核对最近提交版本。过期快照被拒绝，不进入重试队列；已失败的修改也不会被下一次操作静默覆盖。
- 检测四角单独作为处理缓存保存，后台不会改写用户裁剪、旋转及页序。缺失的检测缓存可在编辑时重新识别。
- 高清处理结果先写应用临时区，再在文档锁内检查墓碑、页面 ID、内容版本和处理参数后发布。过期结果直接丢弃；完成或失败后清理本次暂存文件，中断遗留缓存写入超过 24 小时后清理。原图不按缓存过期规则删除。
- 删除先可靠记录墓碑；缓存和 PDF 发布都检查删除状态，PDF 还检查当前文档指纹。后台任务不能重建已删除的文档。
- 打印时在 IO 阶段复制已有 PDF 到独立临时快照，不重复编码；系统打印结束后删除快照。文档后续编辑或删除不改变打印任务正在读取的文件。

## 失败与恢复

保存组件统一保留错误和重试快照，首页也能显示失败提示、再次提交。失败操作不提示成功；已提交清单和原图继续有效。暂未提交成功的修改在当前进程中保留重试，进程终止后恢复最后一次有效清单；不把未确认操作计为已保存。

相机初始化前快门暂不可用，避免初始化窗口的点击被静默忽略；该条件只依赖相机就绪，与实时识别成功与否无关。

## 可重复验证

沿用项目现有 JDK 21、Android SDK 及本地 Gradle 缓存：

```powershell
$env:JAVA_HOME="$PWD/.gradle-local/jdks/eclipse_adoptium-21-amd64-windows.2"
$env:ANDROID_HOME='C:/Users/Lenovo/AppData/Local/Android/Sdk'
$env:ANDROID_USER_HOME="$PWD/.gradle-local/android"
./gradlew.bat --gradle-user-home .gradle-local :app:assembleDebug :app:assembleDebugAndroidTest :app:testDebugUnitTest --no-daemon '-Pkotlin.compiler.execution.strategy=in-process' --max-workers=2
./tools/run-immediate-save-e2e.ps1
./tools/run-history-rescan-e2e.ps1
./gradlew.bat --gradle-user-home .gradle-local :app:lintDebug --no-daemon --max-workers=2
```

专项脚本覆盖真实拍摄、左上角返回和系统返回、连续编辑、独立新扫描、后台完成、可靠清单/索引故障、旧快照拒绝、导入合并及删除与 PDF 并发。另在五页拍摄已确认、尚未进入预览的断点直接强制终止进程，再分两个新进程恢复、编辑和再次恢复。终止前保存的断点包含 PID、页面 ID、原图 SHA-256 和待处理页数；预期终止的 instrumentation 不冒充通过用例。

工件固定输出到本地 `output/immediate-save-e2e/`，包括测试结果、截图、导航/快门耗时、原图尺寸和进程恢复断点；原有回归工件在 `output/history-rescan-e2e/`。重复执行覆盖同名工件，扫描图片不提交 Git。
